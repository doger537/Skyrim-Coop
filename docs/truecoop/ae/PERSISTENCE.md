# Продолжение AE: постоянное состояние

## Контрольная точка G — хранилище

Добавлен отдельный `TrueCoopState`, без зависимости от движка. SQLite 3.46.0
закреплена в xmake. Один сервер эксклюзивно владеет файлом мира; WAL и
`synchronous=FULL` используются для атомарной фиксации. Каждая запись защищена
SHA-256 от ключа, ревизии и payload. Пакет изменений либо фиксируется целиком,
либо откатывается. Запись с устаревшей ревизией не заменяет новую.

Первичная проверка: 33 Catch2-теста, 665 assertions, exit 0. Есть отдельные
сценарии открытия существующего мира, конфликта ревизии, ошибки внутри пакета,
повреждения payload и попытки второго сервера открыть тот же файл. Чужая БД и
неизвестная версия схемы отклоняются. Файлы не пересоздаются для обхода ошибки.

Эта точка проверяет хранилище. Подключение игровых сервисов выполняется следующим
пакетом. Это ещё не доказательство сохранности игрового сейва или всей кампании.

## Контрольная точка H — контракт, контейнеры и замки

Реализовано сохранение контракта контента между перезапусками. Серверные ModId
восстанавливаются из закреплённого порядка имён, а записи объектов имеют ключ
plugin+localFormId. В payload отсутствуют временные ECS ServerId. До открытия
мира проверяются SHA-256 всех записей; ошибочная БД не заменяется пустой.

Первоначальные снимки контейнеров фиксируются одной транзакцией. Изменения
инвентаря/замка сохраняются до изменения ECS и рассылки. При уходе последнего
игрока ECS может освободиться, но запись остаётся в БД. Новая регистрация объекта
получает сохранённый снимок, а старый клиентский upload его не заменяет.

Клиент очищает старые object entity IDs при отключении, запрашивает объекты при
повторном входе в ту же ячейку и применяет также явно незапертый замок. Сохранение
зачарований включает эффекты; разные эффекты больше не считаются одной стопкой.

Unit-проверка этого пакета: **39 тестов, 863 assertions, exit 0**. Сетевая проверка
нового процесса и аварийного перезапуска проводится далее. Windows/Skyrim не
запускались: **«Реализовано, игровая проверка не выполнена»**.

Путь: `Persistence:sWorldPath`, по умолчанию `Data/TrueCoop/world.sqlite3` в папке
сервера. Поддерживаются статические контейнеры/двери и предметы с маппируемыми
формами; динамическое зачарование восстанавливается прежним клиентским кодом из
эффектов. Динамические определения базовых предметов/ячеек пока не поддержаны.
Для домов должна быть включена прежняя настройка `Gameplay:bSyncPlayerHomes`.

Перенос предмета между игроком и контейнером по-прежнему приходит как отдельные
дельты. Проверка количества предотвращает отрицательный серверный остаток, но
не заменяет атомарный transfer RPC и откат клиентского предсказания. При таком
конфликте сервер останавливается с причиной, сохраняя последнюю принятую БД;
конкурентный подбор последней вещи ещё не объявляется исправленным.

Основание настроек: [SQLite PRAGMA](https://sqlite.org/pragma.html), режимы locking,
journal и synchronous. Не копировать только основной файл работающей WAL-базы:
для резервирования остановить сервер или использовать SQLite backup API.

## Проверка H через настоящий серверный процесс

Сборка `b0363205`, Linux x86_64, GCC 14.2.0, xmake 3.1.0. Пройдены все
20 прежних сетевых сценариев на синтетическом профиле 5 базовых + 74 CC.
Дополнительно: последний клиент вышел из ячейки, затем ушёл с сервера; новый
клиент получил сохранённые 8 вещей и замок уровня 49 вместо своего upload 999.
Те же значения восстановлены новым серверным процессом после `/quit`.
Перед SIGKILL сделаны новые операции +1/-1 и unlock/lock; WAL имел 37112 байт.
После аварийного запуска подтверждены 8 вещей и актуальный замок. Эти проверки
не используют Skyrim и не подтверждают правильность отображения в игре.

## Контрольная точка I — общий сохраняемый журнал квестов

Журнал принадлежит WorldId, а не группе. Перед рассылкой этапа/старта/остановки
сервер атомарно фиксирует снимок квеста и запись события. Ключ содержит имя
плагина и локальный FormID. Номер запуска (epoch) отличает повторное прохождение
повторяемого задания от устаревших пакетов. Повторы не сбрасывают историю;
отправитель получает acknowledgement без повторного запуска своего фрагмента.
Личный журнал из AssignCharacterRequest не заменяет общий.

В протоколе `0x54430003` принятый AuthenticationResponse ещё не означает вход
в игровой мир. Сервер передаёт Begin / записи квестов / End. Клиент проверяет
весь снимок, отвечает Ready и только после Accepted публикует ConnectedEvent.
Игровые пакеты до этого игнорируются. При изменении журнала во время проверки
сервер отправляет новый снимок с новым nonce. Есть 90-секундный предел ожидания.

Первый участник нового мира получает единственную lease на импорт baseline.
Он передаёт наблюдаемые завершённые этапы, без предположения о порядке Papyrus.
Импорт всего baseline и маркер его завершения фиксируются одной транзакцией;
другие ожидают. При отключении владельца незавершённый upload отбрасывается,
lease передаётся ожидающему участнику. Повторный импорт запрещён.

Для неподтверждённых квестов требуется соответствующий сейв: недостающий этап,
личный лишний прогресс или различие running/stopped отклоняются до допуска.
Это предотвращает объявление произвольного SetStage полноценным восстановлением
сюжета. Состояние квеста повторно проверяется перед ConnectedEvent. Отключённые
события старого соединения не отправляются после переподключения.

### Декларативные адаптеры

`Persistence:sQuestAdaptersPath` (по умолчанию `config/TrueCoopQuestAdapters.json`).
Отсутствующий файл означает пустой реестр; повреждённый или несовпадающий с миром
файл останавливает открытие мира. В БД закрепляется канонический JSON политики;
его нельзя незаметно заменить после перезапуска. Старый мир H получает пустую
политику один раз без изменения записей объектов.

Схема 1: массив `adapters`, каждый элемент содержит `plugin`, точный `sha256`,
`quest` (локальный hex FormID без 0x), `stages`, `replay_stages`, `evidence`,
`game_verified: true`. Опциональны `allow_misc`, `allow_restart`,
`replay_lifecycle` и `decisions: [{id, stages}]`. Квесты личного старта ASLAL
исключены. Allowlist этапов и взаимоисключающие решения проверяются до записи.
Первое принятое решение остаётся единственным серверным исходом; конфликтующий
клиент отключается с причиной и должен загрузить согласованный сейв.

План replay создаётся полностью до первого применения. Применяются только
разрешённые этапы в сохранённом порядке; bootstrap-события никогда автоматически
не воспроизводятся. Start/stop требуют отдельного допуска; автоматический
restart другого epoch запрещён. Используются существующие ScriptSetStage,
ScopedQuestOverride и защита сцен, без новых адресов или перехватов движка.

Поставляемый пример `GameFiles/Server/TrueCoopQuestAdapters.example.json` пуст.
**Проверенных игровых CC-адаптеров пока нет.** Наличие поля `game_verified`
является заявлением автора конфигурации, а не результатом независимого теста.
Синтетический адаптер из unit-тестов не относится к настоящему квесту Rare Curios.

### Граница результата

Дисковый журнал не сериализует VM Papyrus, aliases, инстансы сцен, награды,
Completed/Failed, все переменные или фракции. Совпадение этапов является
необходимой проверкой, а не доказательством равенства этих состояний. Первый
серверный commit решения не отменяет уже выполненный локальный фрагмент
проигравшего клиента. Предварительное согласование решения до игровых эффектов
потребует отдельного проверенного адаптера/точки интеграции. Нельзя объявлять
единый сохраняемый сюжет и полную AE готовыми на основании этой точки.

NPC death/respawn, календарь, динамически созданные объекты и атомарные переносы
между владельцами остаются отдельными задачами постоянного мира. Mixed active
SE/AE по-прежнему отклоняется; проверенных Limited-профилей нет.
