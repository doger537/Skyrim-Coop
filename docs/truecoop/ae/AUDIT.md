# AE: исходный аудит, 2026-11-14

База: `9b58b425`. Ветка `truecoop/ae-compatibility`, существующая архитектура STR.
Игровых файлов, двух Windows-клиентов и IDA/Ghidra в этой среде нет.
Пользователь подтвердил: сейчас код и автотесты, игровые прогоны отдельно.

## A — что найдено

- `ContentCompatibility` уже сравнивает SHA-256 активных ESM/ESP/ESL и их порядок.
  Числовые локальные слоты намеренно отображаются отдельно через GameId.
- `TransportService` асинхронно читает плагины до аутентификации. Защита поколений
  не позволяет результату старого подключения попасть в новое.
- `GameServer` отклоняет другой BUILD_COMMIT и runtime, неверный пароль,
  запрещённые SKSE/MO2; первый принятый клиент задаёт контракт до перезапуска.
  Отдельной версии схемы и проверки ресурсов/библиотек пока нет.
- `ModSystem::GetGameId` маскирует слишком длинный BaseId: повреждённый ID может
  стать другим допустимым объектом. Начальное местоположение проверяется отдельно.
- `CharacterService`, `InventoryService`, `ObjectService`, `MagicService` используют
  GameId, поэтому им не нужна отдельная ветка по имени каждого CC-плагина.
  Это свойство формата, а не доказательство работы каждой Creation.
- `OperationWindow` подавляет повтор одного пакета, но не делает атомарным
  конкурентный подбор одного предмета разными игроками.
- Объекты удаляются, когда последний игрок покидает ячейку. Постоянного хранения
  всего мира нет. Нельзя обещать восстановление контейнеров после перезапуска.
- Квесты ретранслируются группе, дубликаты стадий подавляются в PartyService.
  Нет единого постоянного серверного журнала решений, универсальной безопасной
  загрузки Papyrus aliases/scenes и проверки всех CC-квестов.
- Alternate Start policy и защита начальных сцен сохраняются. Конкретные версии
  ASLAL/USSEP с AE не подтверждены; фактические masters нужно читать из TES4.
- SkyrimSE.exe версии 1.6.x/1.7.x не доказывает наличие Anniversary Upgrade.
  [Каталог](CATALOG.md) содержит 74 записи, точные MAST и игровые результаты
  пока неизвестны. `_ResourcePack.esl` и поздние Creations учитываются как обычные
  активные плагины, но не добавляются к историческим 74.

## Последовательность и контрольные точки

Каждый законченный пакет исходников получает отдельный git-коммит. Контрольная
точка кода не означает игровую приёмку этапа. При регрессии откатывать отдельный
пакет через `git revert`, сохраняя историю и файлы пользователя; не менять сейвы.

| Этап | Пакет | Игровой барьер |
|---|---|---|
| A | Аудит, реестр 74 Creations, карта ограничений | Проверить файлы реальной установки |
| B | Схема протокола, MAST, SHA-256 ресурсов и библиотек, причины отказа | Два одинаковых клиента и ошибки входа |
| C | Отказ от усечения повреждённых FormID, тесты ESL | Предметы, NPC, магия, активация, конкурентный контейнер |
| D | Матрица общих квестов и требования к адаптерам | Две стороны, решения, награды, поздний вход |
| E | Только явно проверенные профили Limited | Пока ни одного; различия активного контента отклонять |
| F | Регрессия, протокольный probe, записи результатов | Обрыв, переподключение, перезапуск, сейвы |

Новые хуки/offsets и универсальный replay квестовых стадий без анализа движка не
добавлять. Для адаптера нужны фактические QUST/VMAD, скрипты из правомерно полученной
установки, доказательство поведения alias/scene и затем два игровых клиента.
Простой SetStage всем участникам может повторить награды/сцены и испортить прогресс.

Прямое подключение к частному серверу сохраняется. Steam invite требует отдельного
исследования SDK/AppID; не подменять им пароль или лицензию. Сценарий с изменённым
exe не считается подтверждённым; DRM и получение платных ресурсов вне магазина
в проект не добавляются.
