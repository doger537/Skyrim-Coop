# Контракт подключения AE

Статус: реализация проверяется автоматическими тестами. **Реализовано, игровая
проверка не выполнена**. Покупка Upgrade не определяется по версии exe.

Обычное подключение по адресу частного сервера остаётся прежним. Проверки идут до
создания сетевого игрока и установки начального местоположения:

1. Фиксированный префикс схемы `kTrueCoopProtocolVersion`, затем прежний BUILD_COMMIT.
   Старый layout отклоняется до чтения его строк и массива плагинов.
2. Лимит игроков, прежние разрешения SKSE/MO2 и пароль.
3. Поддерживаемый runtime и совпадение с первым принятым клиентом.
4. Имена, порядок, флаги ESL и SHA-256 активных плагинов; MAST из TES4,
   присутствие каждого master и его положение перед зависимым плагином.
5. SHA-256 каждого установленного BSA верхнего уровня Data. Для активной записи
   из каталога 74 обязательно наличие её BSA. Сверяются также реально выбранный
   `versionlib-<runtime>.bin` и DLL загруженного SKSE, если SKSE активен.
6. Один SHA-256 упорядоченного набора loose-файлов из Scripts, Meshes (включая
   HKX/behavior), Textures, Sound, Seq, Strings, Interface и DLL/INI/TOML/JSON
   из SKSE/Plugins. Хеш включает относительное имя с длиной и SHA-256 файла.
7. Начальные GameId проверяются до изменения таблицы серверных ID.

Строгий контракт сохраняется, пока работает сервер, в том числе после выхода всех
игроков. После перезапуска первый принятый клиент снова задаёт контракт: постоянный
серверный профиль и сохранение мира пока не реализованы. BUILD_COMMIT, схема, пароль
и проверки ресурсов не отключаются. Старый `bEnableContentCheck=false` больше не
обходит контракт; ключ сохранён для чтения существующих конфигураций.

При ошибке клиент получает конкретный плагин/ресурс и рекомендуемое исправление.
Для агрегата `data/loose-files` нужно сравнить loose-деревья обоих профилей. Имена
ресурсов нечувствительны к регистру, их порядок перечисления не влияет на контракт.
Локальные слоты плагинов не приравниваются к серверным ID.

## Получить фактические зависимости и хеши установки

Собрать `xmake build TrueCoopContentAudit`. Подать полный порядок **как в движке**,
один UTF-8 filename в строке, включая базовые ESM и автоматически активируемые
записи Skyrim.ccc. Обычный plugins.txt может не содержать их всех. Запускать в той
же виртуальной файловой системе MO2/Vortex, что и игру.

```powershell
TrueCoopContentAudit.exe "D:\Games\Skyrim Special Edition\Data" 1.7.104.0 engine-loadorder.txt > client-a.json
# Если реально загружен SKSE, добавить полный путь его runtime DLL последним аргументом.
```

Инструмент только читает файлы, выводит плагин/слот/ESL/SHA-256/MAST и ресурсы в JSON,
возвращает ненулевой код при ошибке. `manifestValid=true` означает целостность
манифеста, не игровую совместимость. Архивы не распаковываются и не передаются.
JSON можно приложить к записи игровых испытаний без пароля подключения.

## Границы

- Хеширование BSA при каждом подключении требует чтения больших файлов. Оно
  выполняется в worker, без объектов движка. Не менять профиль/файлы во время
  игры; защита времени/размера обнаруживает изменения во время чтения файла,
  но не является блокировкой всей установки на весь сеанс.
- Это консервативный профиль: сравниваются также неактивные BSA и некоторые
  косметические ресурсы. Разные языковые архивы могут вызвать отказ. Limited
  Compatibility ещё не разрешает их различия.
- Ошибки чтения/обхода дерева, неверный TES4, неизвестные расширенные XXXX внутри
  TES4, несовпадение ESL и лимит манифеста 48 KiB приводят к отказу. Нет усечения
  манифеста ради подключения. Один и тот же неправильный набор файлов не становится
  подтверждённо рабочим от совпадения хешей.
- Хеш DLL удостоверяет точное совпадение её версии/байтов между профилями, но не
  подтверждает поддержку её ABI конкретной игрой. Стартовые проверки Address
  Library/SKSE сохранены. Сторонние загрузчики вне перечисленных путей, INI игры,
  MCM и динамическое состояние Papyrus требуют отдельного аудита.
- Схема изменена: весь комплект клиент/сервер/probe нужно пересобрать вместе.
  Обратной совместимости со старой схемой нет.
