# Проверки и игровой протокол

## AE-итерация 2026-11-14

Статусы и реестр: [каталог 74 Creations](docs/truecoop/ae/CATALOG.md).
Автотесты не заменяют испытания двух Skyrim. Для каждой записи выполнять все
применимые строки; «не применимо» требует анализа фактических записей плагина.
Реальный игровой сценарий в этой среде не выполнен.

| ID | Действия двух клиентов | Критерий и что записать |
|---|---|---|
| AE-CONNECT | Полная одинаковая AE, вход по IP, группа, движение/анимации; повторить с третьим участником | Оба видят друг друга; runtime/build/protocol, манифесты, логи, видео |
| AE-REJECT | Изменить ESL, BSA, loose PEX, библиотеку, порядок; убрать master; неверный пароль/сборка | Отказ до создания игрока, причина и исправление, исходная сессия не меняется |
| AE-ITEM | Добыть оружие/броню штатным квестом, передать, экипировать обоими | Правильные модель/эффекты/зачарование; число предметов до/после |
| AE-NPC | Один CC-NPC у обоих: бой/смерть/обыск; выход владельца, другой продолжает | Одна сущность/смерть, корректные HP/AI/ownership, нет повторного лута |
| AE-MAGIC | Каждый применяет CC-заклинания на NPC и второго игрока | Одинаковые эффекты/снаряды/урон, корректная цель и прерывание |
| AE-CELL | Вместе и по очереди войти в новый дом/подземелье, разные переходы | Верные двери/ячейки/объекты, нет недоступных форм и дублей |
| AE-CONTAINER | Одновременно активировать один CC-объект, обыскать одного NPC и забрать последний предмет из одного CC-сундука | Общий итог один; нет отрицательных количеств/дюпа/исчезновения; повторить с задержкой и обрывом |
| AE-QUEST | A завершает стадию, B следующую; затем конфликтующие решения | Общий журнал/цели, один исход, награда один раз; поздний вход и рестарт квеста |
| AE-FISH | Обоими использовать одну рыболовную точку, добычу и квестовые цели | Рыба/анимации/предметы/стадии согласованы, ресурс не дублируется |
| AE-SURVIVAL | Одинаковое выживание, отдых/еда/холод/ожидание и переход ячейки | Политика локальных потребностей и общих часов; нет случайного глобального замедления |
| AE-RECONNECT | Обрыв A во время переноса вещи/стадии/смерти NPC; B продолжает, A возвращается | Актуальное состояние, без повторной награды/начала/дюпа и повреждения сейва |
| AE-WORLD | Изменить CC-дом/замок/контейнер, оба выйти из ячейки; штатный и аварийный перезапуск сервера | Контейнер/замок сохраняются в серверных тестах; полный игровой мир этим тестом ещё не принят |
| AE-START | Закреплённые ASLAL+USSEP+AE, два новых персонажа с общим стартом, повторный вход/поздний участник | Нет повторных начальных сцен; общий сюжет без обязательного Хелгена, prerequisites гражданской войны |
| AE-LIMITED | Только отдельно утверждённый смешанный профиль | Пока allowlist пуста: отказ. Общий одинаковый SE-профиль проверять как строгий |

Каждый прогон: дата/среда, commit и хеши бинарных сборок клиентов/сервера,
версии exe/SKSE/Address Library/ASLAL/USSEP, JSON TrueCoopContentAudit, мод-менеджер,
сейвы до/после, настройки сервера и сети (RTT/jitter/loss), последовательность
действий A/B, ожидаемый/фактический итог, баг, исправление и повторный прогон.
Пароли и токены в отчёты не включать. Исходный игровой прогресс сохранять отдельно.

Автоматическая часть: TPTests; TrueCoopContentAudit на синтетических TES4;
TrueCoopProtocolProbe на новом изолированном приватном сервере, не сервере прохождения.
Probe содержит 74 синтетические записи, проверяет вход/отказы, NPC inventory replay,
поколения движения, общий снимок CC-контейнера/замка при переподключении с другим
игроком в ячейке и подавление дублированных квестовых событий. G–I добавляют SQLite и общий журнал независимо от группы.
Он не запускает Skyrim/Papyrus и не подтверждает работоспособность содержимого BSA.

## Предыдущие сценарии

Статусы игровых A–J ниже: **НЕ ВЫПОЛНЕНО**. Базовые условия: отдельные тестовые персонажи,
резервные копии, одинаковая сборка клиента/сервера и контент, частный сервер.
Поддержка будущих функций проверяется только после их реализации.

| ID | Действия | Ожидаемое наблюдение |
|---|---|---|
| A | Запустить сервер, два клиента, подключить по адресу, создать группу | Оба видят движение другого и состав группы |
| B | Разойтись по разным ячейкам, взаимодействовать с NPC, вернуться | Нет дублей NPC, управление передано, видимые состояния согласованы |
| C | Одновременно забрать одну единицу из тестового контейнера | Суммарно один предмет у игроков, ноль в контейнере; повторить после обрыва |
| D | Положить предмет в тестовый дом, выйти; войти другим персонажем | Точный предмет и количество сохранены |
| E | Подключить SE и SE+Upgrade с зафиксированным списком файлов | Поддержанный ограниченный режим или понятный отказ до игровых эффектов |
| F | Первый выполняет цель 1, второй цель 2 тестового квеста | Журнал/цели/завершение одинаковы, награда не повторяется |
| G | Выполнить событие смерти тестового сюжетного NPC, войти вторым, перезапустить сервер | NPC остаётся погибшим у обоих |
| I | Оборвать соединение во время события; продолжить вторым, подключить первого | Применён актуальный прогресс, нет повторных наград/сцен |
| J | Обычный перезапуск сервера после изменения дома/квеста | Поддерживаемые изменения восстановлены; отдельно проверить аварийный сбой |
| AS | Офлайн создать двух персонажей ASLAL+USSEP, одинаковый старт, подключиться, переподключиться | Общая точка встречи и стартовый прогресс, без повторной инициализации |

Для AS отдельно проверить отложенный запуск основной истории и неизменённые предпосылки гражданской войны.
Для этапа 2 записать фактические задержки, потери/джиттер, частоты обновлений, видимые рывки,
передачу владения, настройки/версии и воспроизводимость; целевые числа выбираются после измерения базы.

На каждый запуск создать запись:

```text
ID / commit клиента и сервера / дата / контент / сценарий:
Условия и сетевые параметры:
Последовательность действий:
Ожидаемый результат:
Фактический результат:
Ошибки и приложенные логи (без паролей/токенов):
Исправление (либо ещё не найдено):
Повторный тест и статус:
```

Автоматические проверки: Tools/TrueCoop/Build.ps1 -CheckOnly; конфигурация xmake;
сборка TPTests и запуск Catch2; Angular production build. Отдельный отчёт текущего запуска: BASELINE.md.

Итерация 2: pure-data проверки content_compatibility.cpp и два регрессионных сценария PlaybackClock.
Headless-сеть: собрать TrueCoopProtocolProbe, запустить НОВЫЙ частный сервер с портом 10582 и
bEnableContentCheck=true, выполнить TrueCoopProtocolProbe.exe 127.0.0.1:10582, остановить сервер /quit.
Этот тест создаёт синтетических игроков/NPC, поэтому его нельзя запускать на игровом сервере прохождения.
Пройденные headless-сценарии не заменяют игровые A–J. См. ITERATION_2.md.

## Дополнительная приёмка G–I

- SERVER-PERSIST: 20 прежних сценариев, уход всех из ячейки и сервера,
  повторная регистрация с устаревшим upload, новый процесс, SIGKILL после новых
  WAL-транзакций. Проверить точные содержимое/замок и отказ изменённому контракту.
- CAMPAIGN-GATE: gameplay до Ready не изменяет мир; одна lease baseline;
  отключение владельца передаёт lease, частичный импорт отсутствует в БД;
  stale nonce не допускает клиента; изменение журнала требует нового снимка.
- CAMPAIGN-RESTART: оба клиента без группы двигают один квест; повторы, новый
  epoch и старые пакеты; после ухода всех и перезапуска остаётся тот же журнал.
- ADAPTER-PIN: другая SHA/политика не открывает существующий мир; неизвестный этап
  или противоположное решение не меняют БД; синтетический fixture явно отделён
  от настоящего CC-квеста.
- GAME-CAMPAIGN: два Skyrim с согласованным сейвом, третья сторона с пропущенным
  и лишним этапом; обязательный отказ до ConnectedEvent. Реальным адаптером
  проверить точный разрешённый replay, сцены, aliases, награды, очереди Papyrus,
  stopped/running, повторяемые задания и изменение прогресса во время входа.
- GAME-DECISION: конфликтующие решения в один момент. Зафиксировать эффекты
  проигравшего локального фрагмента; одного серверного отказа недостаточно для
  объявления этого сценария безопасным.

Статус новых игровых строк: **НЕ ВЫПОЛНЕНО**. Не заменять их unit/probe результатом.
